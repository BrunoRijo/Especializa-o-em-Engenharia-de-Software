# Processo de teste e Tipos de testes 🕵‍♂️ 🐞 
>[!Note]
>Resumo 37, Especialização em Eng. de Software por Bruno Rijo

O processo de teste de software tem objetivo de elaborar métricas para que os testes sejam bem executados. Imagina que alguém te peça para testar um software, o processo de software te ajudaria a saber o “Como?” e “Qual o resultado esperado?”.

Como falei no último resumo, um teste tem como finalidade averiguar se aquilo que foi planejado para ser feito realmente foi feito, durante um teste são inseridos dados fictícios no software e os resultados e comportamentos observados são usados como referência em busca de anormalidades.

Ao se realizar um teste pode se encontrar:

1️⃣ FALHA: Um comportamento inconsistente, ou processamento incorreto dos dados.

2️⃣ ERRO: Relacionado à informação, um desvio do que foi especificado.

3️⃣ DEFEITO/BUG: Decorrente de um código mal escrito, que causa um mal funcionamento.

## Tipos de testes
- **Unitário**:
Avalia cada módulo do sistema de maneira individual, averiguando se o funcionamento está correto.
- **De Integração**: 
Avalia se a comunicação entre os módulos é feita do modo correto.
- **De Sistema**:
Simula o ambiente de uso final, como se fosse o usuário.
- **De Aceitação**:
Averigua a aceitação de um grupo de usuários com aquilo que o programa executa, como uma versão beta liberada para alguns usuários.
- **De Regressão**:
É a reaplicação dos testes anteriores quando uma nova versão é lançada, com fins de confirmar que novos erros apareceram, depois de outros terem sido tratados.
- **De Integridade**:
Verifica a capacidade do sistema de resistir a falhas, é realizado em diversas fases do desenvolvimento para averiguar a robustez do programa.
- **De configuração**:
Avalia a capacidade do programa ser executado e oferecer todas as suas funções em diferentes plataformas. 
- **De instalação**:
Avalia possíveis erros em vários cenários de instalação como hardware, espaço em disco, etc ..
- **De Performance**:
Avalia a excelência do que foi desenvolvido, em termos satisfação de velocidade de execução.
- **Não Funcionais**:
Como o nome sugere, relaciona-se aos requisitos não funcionais.
