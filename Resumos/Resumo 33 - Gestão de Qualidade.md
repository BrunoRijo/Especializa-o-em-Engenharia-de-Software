# Gestão de Qualidade 📑 
>[!Note]
>Resumo 33, Especialização em Eng. de Software por Bruno Rijo

Para Bessin (2004, p. 2 apud PRESSMAN, 2016, p. 414), a qualidade de software pode ser definida como uma gestão de qualidade efetiva aplicada de modo a criar um produto útil que forneça valor mensurável para aqueles que o produzem e para aqueles que o utilizam.

A definição da qualidade de software depende de vários fatores como: Tecnologia utilizada, Nível de conhecimento dos usuários, das Regras de negócio e do tratamento de dados e informações, entre outros. 

PRESSMAN, afirma que o processo de software ou SPI (Software Process Improvent), que se compreende da seguinte maneira: Processo de software definido, Abordagem organizacional e estratégia para a melhoria. 

A organização que acredita na melhoria do processo de software percebe que a cultura organizacional é fundamental para suportar a transição tecnológica, determinar o nível em que se encontra, proporcionar a preparação para absorver as mudanças no processo e medir o nível após a adoção das mudanças.

Durante a implantação do processo de melhoria é natural que haja uma certa resistência nas organizações a adesão do mesmo, quando estão acostumadas a uma cultura anterior diferente.. É indiscutível que as ações de qualidade exigem uma adequação organizacional.

O SPI tem uma proposta ampla e completa com atividades-base denominadas IDEAL, que é uma sigla para Iniciar, Diagnosticar, Estabelecer, Agir e Aprender. É necessário encontrar o equilibrio entre entregar os requisitos estabelecidos no escopo e utilizar de forma adequada os recursos dentro do prazo combinado com o cliente, dessa forma, é possível alcançar um nível de qualidade satisfatório para a operação dos negócios. Para isso, a equipe precisa definir um método  para controlar a qualidade, desde que esse métodos possua os princípios de melhoria do SPI.

O CMMI (Capability Maturity Model Integration) é um metamodelo que sugere cinco níveis de maturidade no processo de software. É utilizado em larga escala pelas grandes organizações por ter uma proposta de melhoria contínua. É o principal indicador de qualidade do processo de software, é feita uma classificação  em níveis de capacidade organizacional através de uma avaliação das atividades desempenhadas em cada processo, sempre referenciadas por metas. Os níveis de CMMI são: Incompleto, Executado, Controlado, Definido, Controlado quantitativamente e Otimizado.

Nas metodologias ágeis a qualidade de software é obtida através dos processos de sprint review e de avaliação da sprint, quando se discute todo o processo, desde que ocorreu na iteração até os problemas de qualidade
